# SEO 실행 계획 (2026-10-14 점검 기준)

색인을 막거나 페널티를 부르는 긴급 문제는 없다. 각 항목의 근거는 FULL-AUDIT-REPORT.md에 있다.

## 1단계 — 배포 (이번 주)

이번 점검에서 고친 7건(메타데이터 `<head>` 고정, 한국어 홈 제목, 블로그 x-default 등)은 리디자인 브랜치에만 있다. 배포해야 운영에 반영된다.

- [ ] 리디자인 브랜치 커밋 → main 병합 → Vercel 자동 배포
- [ ] 배포 후 확인 1: Googlebot이 받는 HTML의 앞부분에 title·canonical이 있어야 한다.

```bash
curl -s -A "Mozilla/5.0 (compatible; Googlebot/2.1; +http://www.google.com/bot.html)" https://www.jeongwoohrd.com/ | head -c 10000 | grep -o '<title>[^<]*</title>'
```

- [ ] 배포 후 확인 2: 출력이 없어야 한다.

```bash
curl -sI https://www.jeongwoohrd.com/ | grep -i x-powered-by
```

- [ ] Google Search Console, 네이버 서치어드바이저, Bing 웹마스터도구 등록 여부를 확인하고 사이트맵(`https://www.jeongwoohrd.com/sitemap.xml`)을 제출한다. 홈 URL은 색인 생성을 요청한다.

## 2단계 — 결정이 필요한 빠른 수정 (1~2주)

| 항목 | 회사가 정할 것 | 작업량 |
|---|---|---|
| 영문 짧은 회사명 꼬리표(예: "Jeongwoo HRDI"). en·vi·ne·lo 제목 대부분이 60칸 안으로 들어온다 | 영문 약칭 | 작음 |
| 비자 페이지 제목·설명을 핵심어 먼저, 한글 30자·영문 60자 안팎으로 정리(ko 9개, ja 12개 포함) | 문구 승인 | 중간 |
| 설명 50자 미만 5개 보강(/partners, /gallery, /ja/gallery, /ja/blog, /ja/partners) | 문구 승인 | 작음 |
| WebSite 구조화 데이터 이름을 한글로 고정, 영문은 alternateName | 브랜드 표기 | 작음 |
| Organization에 설립일(2026-06-10)·대표 넣고 주소를 시·구·도로명·우편번호로 분리 | 우편번호 확인 | 작음 |
| 사업영역 상세: 화면에 경로 표시를 넣고 Breadcrumb을 3단계로, 돌봄 상세에 Service 추가 | 없음 | 작음 |
| llms.txt·llms-full.txt를 블로그 데이터로 생성하는 라우트로 바꾸고 글 수 테스트 추가(현재 36편으로 적혀 있으나 실제 54편) | 없음 | 작음 |
| 폰트(2.06MB)를 Pretendard 글자 묶음별 분할 파일로 바꿔 필요한 묶음만 받게 하기(로컬 호스팅, `unicode-range`) | 없음 | 중간 |
| 홈·블로그를 ISR로 전환해 CDN 캐시 사용. 예약 글은 공개 시점에 `revalidatePath` | 예약 글 공개가 늦어져도 되는 시간(예: 5분) | 중간 |

## 3단계 — 콘텐츠와 신뢰 (1~2개월)

- [ ] /about·/why·/contact를 사실만으로 보강한다(각 400~600어절). 법인 정보, 대표와 담당 역할, 정부 경로와 회사 역할의 구분, 하지 않는 일, 응대 언어와 시간을 넣는다. 확인되지 않은 실적이나 수치는 쓰지 않는다.
- [ ] 실제 계정을 만든다: Google 비즈니스 프로필, 네이버 플레이스, LinkedIn 회사 페이지, 실제 교육 현장 영상이 있는 YouTube. 만든 뒤 Organization `sameAs`에 넣는다.
- [ ] 협력기관에 사실에 맞는 협력 소개와 링크를 요청한다.
- [ ] 블로그·비자 페이지에 실제 검토 담당자 이름과 검토일을 단다(실제로 검토한 글에만).
- [ ] 돌봄·숙박 사업영역 상세의 영어판을 만든다(검수된 사실만).
- [ ] /partners에 기관별 역할, 상태와 날짜, 기관 사이트 링크를 보강한다.
- [ ] 핵심 페이지별로 실사 기반 OG 이미지를 만든다.

## 4단계 — 운영과 모니터링 (지속)

- [ ] 월 1회 Search Console에서 색인 상태와 검색 성과를 보고, 실사용 Core Web Vitals(CrUX)를 확인한다.
- [ ] 내용이 실제로 바뀐 페이지만 사이트맵 lastmod를 갱신한다.
- [ ] CSP를 Report-Only로 시작해 위반 보고를 본 뒤 적용한다. HSTS는 서브도메인 HTTPS 여부를 확인하고 includeSubDomains를 붙인다.
- [ ] 새 글이 공개될 때 사이트맵과 llms.txt에 반영되는지 확인한다.
- [ ] 학습 전용 크롤러(CCBot 등) 허용 여부를 정한다.

## 고치지 않고 남겨 둔 것과 이유

| 항목 | 이유 |
|---|---|
| 제목·설명 문구 | 6개 언어 문구와 영문 약칭은 회사가 정해야 한다 |
| WebSite 이름 표기 | 브랜드 표기 결정 |
| ISR 전환 | 예약 발행이 즉시 반영되는 현재 동작이 바뀐다 |
| 신뢰 페이지 본문, 저자 표기 | 사실 확인과 실제 담당자가 필요하다(실적·자격을 지어내지 않는다는 원칙) |
| sameAs | 실제 계정이 아직 없다 |
| 돌봄 상세 제목 | lp-v1 테스트가 문구를 SHA로 잠가 두었다 |
