1번은 이렇게 확인했다.

- 운영 사이트 `https://www.jeongwoohrd.com/`을 Googlebot UA로 받으면 `</head>`는 3,880번째 문자에서 닫히고 `<title>`은 141,768번째 문자에 나온다. `/blog`도 같다.
- Bingbot UA로 받으면 `<head>` 안에 있다. Next.js 15가 일부 봇에만 메타데이터를 `<head>`에 넣기 때문이다.
- Google은 JavaScript 실행 후 다시 읽을 가능성이 높지만, 원본 HTML의 `<body>`에 있는 canonical은 무시될 수 있다. JavaScript를 실행하지 않는 AI 크롤러(GPTBot, ClaudeBot, PerplexityBot)는 확실히 영향을 받는다.
- 수정 후에는 Googlebot·GPTBot·일반 브라우저 UA 모두에서 title·canonical·x-default·og:title이 `<head>` 안에 있다.

재발 방지 테스트를 추가했다.

- `npm run test:seo` (18 → 20개): 블로그 x-default가 사이트맵과 같은지, `htmlLimitedBots`·`poweredByHeader` 설정이 유지되는지 확인한다.
- `npm run test:seo:live`: 모든 URL에서 title·canonical·x-default가 `<head>` 안에 있는지, 제목에 회사명이 있는지 확인한다. 사업영역 상세 8개 URL은 설계대로 ko·ja·x-default 세 개만 정확히 선언했는지 본다(전에는 6개 언어를 기대해 리디자인 전부터 실패하던 검사).
- 수정 전 빌드에 이 검사를 돌리면 `/`에서 실패했고, 수정 후에는 164개 URL이 모두 통과했다.

## 4. 분야별 결과

### 4.1 기술 SEO — 79 → 약 84

잘 된 점:

- **HTTPS와 정식 호스트.** http→https, apex→www, 구 도메인 joongwoohrd.com이 경로·쿼리를 유지한 채 308로 한 번에 이동한다.
- **robots.txt.** 내부 화면(/sales, /login, /auth, /unauthorized)만 막고 사이트맵을 선언하며, 주요 AI 검색 크롤러를 명시적으로 허용한다.
- **사이트맵.** 164개 URL 모두 200이고 리디렉션이 없으며 hreflang이 들어 있다.
- **canonical.** 모든 페이지에 하나씩, 절대 https 주소로 자기 자신을 가리킨다. noindex는 없다.
- **hreflang.** 서로 참조가 맞고, 사업영역 상세는 의도대로 ko·ja·x-default만 있다.
- **렌더링.** 본문이 모두 서버 렌더링 HTML에 있다.
- **404.** 없는 주소는 진짜 404를 돌려준다(soft 404 아님).
- **보안 헤더.** nosniff, X-Frame-Options DENY, Referrer-Policy, Permissions-Policy, HSTS가 있다.

남은 문제:

| 심각도 | 문제 | 근거 | 권장 |
|---|---|---|---|
| 중간 | 홈 6개·블로그 60개 URL이 `Cache-Control: no-store`로 요청마다 서버 렌더링 | 운영 `/` 응답 `x-vercel-cache: MISS`. 원인은 예약 발행을 위한 `lib/blog.ts`의 `noStore()`와 블로그 상세의 `force-dynamic` | ISR(`revalidate`)로 바꾸고 예약 글이 공개될 때 `revalidatePath`를 호출. 예약 글 공개가 몇 분 늦어도 되는지 결정 필요 |
| 중간 | Content-Security-Policy 없음 | 운영 응답 헤더 | `Content-Security-Policy-Report-Only`로 시작(PostHog, Next 인라인 스크립트 고려) |
| 낮음 | 정적 페이지 104개의 lastmod가 2026-07-19로 고정 | `CONTENT_LAST_MODIFIED` 상수 | 내용이 실제로 바뀐 페이지만 갱신. 디자인 변경은 해당 없음 |
| 낮음 | HSTS에 includeSubDomains·preload 없음 | 운영 응답 헤더 | 모든 서브도메인이 HTTPS인지 확인한 뒤 |
| 참고 | http + apex 조합(`http://jeongwoohrd.com`)은 2단계 리디렉션 | Vercel의 HTTPS 강제 후 앱 리디렉션 | 조치 불필요 |
