# 블로그 예약 공개 운영

## 현재 상태

2026년 10월 배치의 15개 주제·90개 번역은 `status: review`, `publishedAt: null`입니다. [검토 목록](2026-10-review.md)에서 원고를 확인하고 공개 승인을 받은 뒤 아래 작업을 수행합니다. 날짜를 과거로 소급하지 않습니다.

기존 Codex `draft-pr` 자동화는 초안 PR을 만드는 별도 작업이며 중지 상태를 유지했습니다. 여기서 구현한 공개 방식은 배포된 사이트가 요청 시각을 확인하는 방식입니다. 승인·예약 파일을 배포한 뒤에는 데스크톱 자동화를 실행하지 않아도 됩니다.

## 승인 후 적용

`company` 폴더에서 먼저 일정을 미리 봅니다. 아래 시각은 예시입니다. 현재보다 미래인 실제 시작 시각으로 바꾸세요.

```sh
npm run blog:release -- --start=2026-10-02T09:00:00+09:00
```

승인한 원고와 일정을 확인한 후 저장합니다.

```sh
npm run blog:release -- --start=2026-10-02T09:00:00+09:00 --apply
npm run validate:blog
npm run test:blog
npm run typecheck
npm run build
```

이후 회사 사이트의 기존 배포 절차를 실행합니다. **예약 파일을 저장하는 것만으로 운영 사이트가 바뀌지는 않습니다.** 첫 공개 시각 전에 배포를 완료하고, 실제 배포 환경에서 직접 URL·목록·홈 추천·사이트맵을 확인합니다. 첫 시각을 놓쳤다면 지난 날짜로 배포하지 말고 아직 미공개인 글의 일정을 새 미래 시각으로 조정합니다.

첫 3개 주제는 지정한 시작 시각에, 나머지 12개는 다음 월·수·금 오전 9시(Asia/Tokyo, 한국과 동일)에 한 주제씩 공개됩니다. [`release-plan.json`](../../content/blog/release-plan.json)의 순서가 기준입니다. 여섯 번역을 모두 검사한 뒤 같은 승인·예약 시각을 저장합니다. 번역 누락, 이미 공개·예약된 원고, 30일을 넘긴 출처 확인 기록이 있으면 중단합니다.

## 상태와 날짜

| 원본 상태 | 공개 환경 | 날짜 처리 |
| --- | --- | --- |
| `review` | 목록 제외, 직접 URL 404, 사이트맵 제외 | 게시일 없음 |
| `scheduled`, 예약 시각 전 | 목록 제외, 직접 URL 404, 사이트맵 제외 | 승인·예약 시각만 저장 |
| `scheduled`, 승인·예약 시각 이후 | 공개 글로 처리 | 실제 공개 가능 시각의 일본 날짜를 게시일로 표시 |
| 기존 `published` | 기존 방식으로 공개 | 기존 실제 게시일 보존 |

예약은 요청 시 판단합니다. 별도 배치 작업이 원고 파일의 상태를 덮어쓰지 않습니다. 원본 `publication.approvedAt`·`scheduledAt`을 보존하고 화면·메타데이터·구조화 데이터·사이트맵에 공개 상태를 반영합니다. 게시일은 최초 열람 시각이 아닌 공개가 시작되는 날짜입니다.

블로그, 홈의 최신 글과 사이트맵은 정적 빌드 날짜에 고정되지 않도록 요청마다 공개 여부를 판단합니다. 렌더링 안에서는 동일한 현재 시각을 사용합니다. 이미 열린 브라우저에서는 다음 요청·새로고침 시 반영됩니다. Markdown과 이미지 목록은 Next.js 파일 추적에 포함됩니다. 정적 HTML 내보내기 방식으로 바꾸면 이 예약 방식도 다시 설계해야 합니다.

## 검토 환경

```sh
BLOG_INCLUDE_REVIEW=1 npm run start -- --hostname 127.0.0.1 --port 3101
```

개발 서버, Vercel Preview 또는 `BLOG_INCLUDE_REVIEW=1`에서는 검토·예약 원고를 볼 수 있습니다. 검토 글과 이를 포함한 블로그 목록은 `noindex`이며 검토 글에는 BlogPosting 구조화 데이터와 공개 번역 대체 링크를 넣지 않습니다. 사이트맵은 검토 환경에서도 공개 글만 포함합니다. 운영 환경에는 `BLOG_INCLUDE_REVIEW=1`을 설정하지 마세요.

## 공개 보류·변경

공개 전에 해당 주제의 여섯 원고를 모두 `review`로 되돌리고 `publication`을 제거한 다음 다시 배포하면 예약을 보류할 수 있습니다. 변경된 일정을 적용할 때도 여섯 언어의 상태와 시각을 맞추고 콘텐츠 검증을 실행합니다. 이미 공개된 글의 날짜·승인 기록은 덮어쓰지 않습니다.

출처 확인일은 원고 승인이나 예약 때문에 자동 갱신하지 않습니다. 정책이 바뀌면 공식 자료를 다시 확인하고 본문·출처 기록을 함께 수정합니다. 기존 54개 글의 출처 이력 해시 검증은 유지합니다.
