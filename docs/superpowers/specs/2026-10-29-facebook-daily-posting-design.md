# 페이스북 일일 게시 자동화 설계

## 의도

정우인재개발원 페이스북 페이지에 매일 사진 1장과 글 1건을 올린다. 페이지는
2026년 10월 말에 개설된 신규 페이지이며, 개인 프로필이 아닌 "페이지"(교육
컨설턴트)로 확인되었다. 페이지 ID는 `61595913932801`.

> **2026-11-01 정정.** 위 번호는 **브라우저 주소창의 번호**이고 Graph API는 이 번호를 모른다
> (`GET /61595913932801` → code 100 subcode 33). API가 쓰는 페이지 ID는 **`1487730074413949`**다
> (`GET /me/accounts`로 확인). 구현은 후자를 쓴다 — `scripts/facebook/config.py`의 `PAGE_ID` 주석 참고.

최우선 목적은 **일본에 체류 중인 베트남·미얀마·네팔 출신 학생을 한국 유학으로
연결**하는 것이다. 글을 읽고 페이스북 메시지로 문의가 오는 것이 유일한 전환
지점이며, 현 시점에 회사가 약속할 수 있는 것은 **무료 상담**까지다. 패키지 상품,
합격 보장, 비용 보장은 약속하지 않는다.

매일 손으로 글을 쓰고 그림을 뽑는 일은 지속되지 않는다. 한 달에 한 번
몰아서 만들고, 한 번 검토하고, 나머지 한 달은 손대지 않는 구조로 만든다.

## 대상 독자 (사업주의 말 그대로)

1. 베트남·미얀마·네팔 현지에서 한국 또는 일본 유학을 희망하지만, 돈이 부족해
   비용이 낮은 한국 쪽이 맞는 학생.
2. 이미 일본에 있는 베트남·미얀마·네팔 사람으로, 한국에 가고 싶었으나 기회를
   얻지 못해 일단 일본에서 유학 중인 학생.
3. 일본에 관심이 있어 일본에서 유학 중이지만, 외국인 정책이 나빠지는 것을 보고
   다른 길을 찾는 학생.

2번과 3번이 최우선이다.

## 목표

- 매달 한 번의 작업으로 30일치 게시물이 페이스북에 예약된다.
- 사람 손이 가는 작업은 **이미지 30장 생성 1회**와 **검토 1회**뿐이다.
- 검증되지 않은 사실이 현지어로 자동 게시되는 일이 없다.
- 세 언어(베트남어·미얀마어·네팔어)에서 뜻이 어긋난 본문이 나가지 않는다.

## 비목표

- 팔로워 확보, 광고 집행, 그룹 활동 등 **유통**. (이 설계는 "볼 사람이 생겼을 때
  보여줄 것이 쌓여 있는 상태"만 만든다.)
- 받은 메시지에 대한 자동 응답 또는 응대.
- 인스타그램·틱톡 등 다른 채널 동시 게시.
- 이미지 자동 생성. 사업주가 ChatGPT 화면에서 직접 뽑기로 결정했다.
- 게시 성과 분석·리포트.

## 안티골 (기술적으로 동작해도 실패인 것)

- **검증되지 않은 학비·비자·아르바이트 시간 수치가 현지어로 나가는 것.** 읽는
  사람은 인생을 거는 결정을 하고 있고, 사업주는 세 언어를 읽을 수 없다. 이것이
  가장 큰 실패다.
- 회사가 실제로 제공하지 못하는 것(합격 보장, 취업 보장, 비용 보장)을 암시하는
  문구가 나가는 것.
- 미얀마 문자나 데바나가리가 깨진 이미지가 게시되는 것.
- 되번역했을 때 한국어 원문과 뜻이 달라지는 본문이 나가는 것. (어투의
  자연스러움은 검수 인력이 없어 보장하지 않는다. "현지어 품질과 문의 응대"
  참고.)

## 제약

### 콘텐츠

- 소재 1개 → 게시물 3건. 베트남어 → 미얀마어 → 네팔어 순으로 하루 1건씩 3일.
  한 달에 소재 약 10개, 게시물 약 30건.
- 소재 선정은 설계·구현 측 재량. 대상 독자의 관심사에서 뽑는다.
- 형식은 **사진형**으로 확정: 글자가 들어가지 않은 AI 생성 사진 1장 + 현지어 본문.
  (카드형·비교표형은 검토 후 탈락. 이미지 모델이 미얀마 문자와 데바나가리를
  제대로 못 그리기 때문.)
- 모든 게시물의 마지막은 **무료 상담 안내 + 페이스북 메시지 요청** CTA로 끝난다.
- 소재 하나당 이미지는 1장을 3번 쓰지 않고 언어별로 3장을 따로 만든다.
- **이미지는 삽화로만 쓴다.** 실존 인물, 특정 대학 캠퍼스, 회사 시설처럼 보이는
  장면은 생성하지 않는다. AI로 만든 그림이 회사의 실제 기록 사진으로 읽히면
  안 된다. (`CLAUDE.md`의 "생성형 AI 편집 사진 비게시" 규칙은 `company/`
  갤러리의 실사진을 AI로 손대는 경우를 막는 것이므로, 처음부터 삽화로 만드는
  이 경우에는 적용하지 않는다. 사업주가 ChatGPT 이미지 사용을 명시적으로
  선택했다.)

### 운영

- 이미지는 사업주가 ChatGPT 화면에서 수동 생성한다. 따라서 **이미지 생성
  프롬프트와 저장할 파일명을 시스템이 지정해 주어야 한다.**
- 검토 화면에는 현지어 본문 옆에 **한국어 원문을 반드시 병기**한다. 사업주가
  읽을 수 없는 언어이므로 이것이 유일한 검토 수단이다.
- 월 1회 실행. 상시 가동되는 서버나 켜둔 컴퓨터를 전제하지 않는다.

### 플랫폼 (확인 완료)

- 본인이 관리자인 페이지이므로 **Meta 앱 심사와 사업자 인증이 필요 없다.**
  타인 페이지에 게시할 때만 필요하다.
- 필요 권한: `pages_manage_posts`, `pages_read_engagement`, `pages_show_list`.
- 사람 계정의 페이지 토큰은 비밀번호 변경 시 무효화되므로, **비즈니스 관리자의
  시스템 사용자 영구 토큰**을 쓴다.
- 예약 게시는 `published=false` + `scheduled_publish_time`으로 한다. 현재부터
  10분 이후 ~ 75일 이내만 가능하므로 30일치 예약은 한 번에 들어간다.
- 구현 전에 Meta 현재 레퍼런스에서 권한명과 예약 창 상한을 재확인할 것. 위
  내용은 2026년 10월 기준 조사 결과다.

### 저장소 관례

- 독립 실행 스크립트는 `scripts/*.py`, 의존성이 있으면 `uv run --script`,
  루트 `package.json`에 npm 스크립트로 노출한다.
- 산출물은 `output/` 아래. 문서·주석·오류 메시지는 한국어.

## 공정

다섯 단계이며, 1과 4는 사람이, 2·3·5는 스크립트가 맡는다.

1. **플랜 생성** — Claude Code 세션에서 그달의 소재 10개, 게시물 30건의 한국어
   원문과 현지어 본문, 이미지 프롬프트 30개를 만들어
   `output/facebook/YYYY-MM/plan.json`에 쓴다.
2. **이미지 투입** — 스크립트가 프롬프트와 지정 파일명을 출력한다. 사업주가
   ChatGPT에서 뽑아 `output/facebook/YYYY-MM/images/`에 저장한다.
3. **검증** — 이미지 누락, 미해결 사실 플래그, 본문 길이, 금지 표현, CTA 누락,
   날짜·언어 순서를 기계적으로 막는다. 하나라도 걸리면 5단계로 못 넘어간다.
4. **검토** — 정적 HTML을 열어 한국어 원문·현지어 본문·이미지를 나란히 보고
   승인한다.
5. **예약 게시** — Graph API로 30건을 예약한다. 성공/실패를 기록한다.

## 사실 데이터

`output/facebook/facts.json`에 사람이 확정한 사실만 보관한다. 학비, 비자 종류와
요건, 아르바이트 가능 시간 등. **본문 생성 시 이 파일에 없는 수치는 쓰지
않는다.** 필요하면 수치 없이 서술하거나 플래그를 남겨 3단계에서 막히게 한다.

각 항목은 값과 함께 **출처, 확인한 사람, 확인일, 유효기한**을 갖는다. 학비는
매년, 출입국 규정은 수시로 바뀐다. 3단계 검증은 유효기한이 지난 항목을 쓴
본문을 막는다.

저장소에는 이 사업의 사실 기반이 아직 없다. 루트 위키는 네팔→일본 특정기능이고,
`company/messages/visa/*`의 D-2·D-4 안내는 유학생을 채용하려는 **한국 기업
관점**이라 학비·생활비·주당 아르바이트 시간·TOPIK 요건 같은 수치가 없다. 일본
체류 중인 외국인이 한국 유학으로 넘어가는 경로도 다루지 않는다.

사업주 확인: **비자 요건과 아르바이트 허용 시간은 법령으로 정해져 있다.** 즉
회사가 만들어 내는 값이 아니라 공개된 공식 정보이므로, 구현 단계에서 법무부·
하이코리아 등 **1차 출처를 찾아 `facts.json`을 채우는 것이 빌더의 일**이다.
사업주를 기다릴 필요가 없다. 각 항목은 반드시 1차 출처 URL과 확인일을 단다.

단, **학비는 법으로 정해지지 않는다.** 고등교육법에 인상률 상한이 있을 뿐
금액은 대학마다 다르므로, 쓰려면 대학별 공시 등록금을 각각 가져와야 한다.
대학별 금액을 확보하지 못하면 그 게시물에서는 금액을 쓰지 않는다.

`facts.json` 초기 입력은 이 설계의 **선행 작업**이며, "매달 한 시간" 성공
기준에 포함되지 않는 1회성 비용이다.

### 대학 실명

사업주 확인: **"한국에 어떤 대학들이 있는지 소개"하는 맥락에서는 실명을 써도
된다.** 즉 공개 정보로서의 대학 소개는 허용된다.

따라서 게시물에서 대학 실명은 소개 맥락에만 쓰고, **협력 관계·제휴·입학 알선·
합격 가능성과 연결하지 않는다.** "저희 협력 대학", "입학을 도와드립니다" 같은
연결이 대학명과 같은 게시물에 함께 나오면 3단계 검증이 막는다.

출처 데이터는 `company/lib/partnership-network.ts`에 있으나, 그 파일의 주석이
명시하듯 `status`는 활동 상태일 뿐 MOU나 배치 실적이 아니다. 김포대와 한영대는
`planned`로 아직 시작 전이므로 **`planned` 항목은 쓰지 않는다.**

## 설계자가 정한 것

사업주가 위임했거나 명시하지 않아 설계 측에서 정한 사항이다. 뒤집어도 좋다.

- **Python + uv.** 저장소에 이미 같은 형태의 스크립트가 있어 새 도구를 들이지
  않는다.
- **본문 생성은 API가 아니라 Claude Code 세션에서 한다.** 사업주가 이미지에
  유료 API 키를 쓰지 않기로 했으므로, 텍스트에도 별도 키를 전제하지 않는다.
  월 1회 실행이라 이 방식으로 충분하다.
- **게시 시각 기본값은 일본 시간(JST) 저녁.** 최우선 독자가 일본 체류자이기
  때문이다. 네팔 저녁 8시는 일본 밤 11시 45분이라 "각 언어권 현지 저녁"은
  어긋난다. 언어별 오프셋은 설정으로 뺀다.
- **토큰은 `.env`에 두고 커밋하지 않는다.** 시스템 사용자 영구 토큰을 우선으로
  하되, 페이지가 비즈니스 포트폴리오에 들어 있지 않아 발급이 안 되면 장기
  사용자 토큰에서 얻은 페이지 토큰으로 떨어진다. 어느 쪽이든 **토큰 유효성
  점검 명령을 두고, 월 1회 실행의 첫 단계로 돌린다.** 사용자 토큰 경로는
  관리자가 비밀번호를 바꾸면 끊기므로 점검이 특히 필요하다.
- **게시물은 무료 상담까지만 말한다.** 상담 이후의 절차, 비용 부담 주체, 합격·
  입학·취업 가능성은 세 언어 어디에도 쓰지 않는다. 금지 표현 사전에 넣는다.
- **`plan.json`과 `facts.json`은 커밋하고 이미지 30장은 커밋하지 않는다.**
  `output/facebook/*/images/`를 `.gitignore`에 추가한다.
- **검토 화면은 정적 HTML 파일.** 서버를 띄우지 않는다.

## 현지어 품질과 문의 응대

사업주 확인: **원어민 검수자는 두지 않는다. 현지어 작성도, 들어온 문의에 대한
응대도 AI로 한다.** 이에 따라 다음이 정해진다.

- 4단계 검토는 한국어 원문 대조만 한다. 언어별 승인 게이트는 두지 않는다.
- CTA는 현지어로 메시지를 유도해도 된다. 응대 언어를 제한하는 문구를 넣지
  않는다.
- 사람 검수가 없는 대신 기계적 안전장치를 넣는다.
  - **역번역 대조**: 생성된 현지어 본문을 한국어로 되번역해 원문과 의미가
    어긋나는 곳을 3단계에서 표시한다. 어투는 못 잡아도 뜻이 뒤집히는 사고는
    잡는다.
  - **용어집 고정**: 비자 종류, 대학명, 회사명, CTA 문구는 언어별로 한 번
    확정해 `facts.json` 옆에 두고 매달 그대로 쓴다. 달마다 표현이 흔들리지
    않게 한다.

남는 위험은 사업주가 감수하기로 했다. 어느 한 언어의 어투가 어색하거나
기계 번역 티가 나도 회사 내부에서는 알아챌 방법이 없다. 문의가 들어오기
시작하면 그 반응이 유일한 피드백이므로, 초기 몇 달은 반응이 특히 저조한
언어가 있는지 지켜볼 것.

## 사업주 측 선행 작업

- 페이스북 페이지를 Meta 비즈니스 포트폴리오에 넣고, 시스템 사용자를 만들어
  페이지를 자산으로 할당한 뒤 영구 토큰을 발급한다. (앱 심사는 필요 없지만
  포트폴리오 편입은 별개 문제다.) 안 되면 위에 적은 폴백으로 간다.
- 페이지 소개란의 상담 가능 언어에 베트남어·미얀마어·네팔어를 추가한다. 현재는
  영어·일본어·한국어만 적혀 있는데, 게시물 CTA는 현지어로 문의를 유도한다.

## 빌더에게 남기는 것

- `facts.json` 초기 입력. 법령·공시 1차 출처를 찾아 값·출처 URL·확인일·
  유효기한을 채운다. 구현의 일부이며 사업주를 기다리지 않는다.
- 역번역 대조를 어떤 방식으로 돌리고 어느 정도 차이를 표시할지.
- `plan.json` 스키마 세부.
- 3단계 검증 규칙의 구체적 목록과 금지 표현 사전.
- 예약 실패 시 재시도·부분 복구 방식.
- 이미지 파일명 규칙.

## 검증

- 토큰 유효성과 페이지 권한을 확인하는 단독 명령.
- 5단계 dry-run: 실제 호출 없이 예약될 30건의 시각과 본문을 출력.
- 실제 게시는 1건 테스트 예약 후 페이스북에서 눈으로 확인하고 지운 다음 전체를
  돌린다.
- 3단계 검증 규칙에는 테스트를 붙인다.

## 성공 기준

매달 사업주가 한 시간 이내의 작업으로 30일치를 올려두고, 그달 안에 사실이
틀렸거나 문자가 깨진 게시물이 한 건도 나가지 않는다.

## 알려진 위험

현재 팔로워가 1명이다. 신규 페이지의 자연 도달은 사실상 0이므로, 이 설계가
완성되어도 당분간 읽는 사람은 거의 없다. 사람을 데려오는 일(광고, 그룹, 기존
상담자 초대)은 이 설계 밖에 있으며 별도로 다뤄야 한다.

응대를 AI로 하기로 한 이상, 문의가 몰리는 시점에 응답 속도와 품질이 그대로
회사의 인상이 된다. 게시는 자동이지만 받은 메시지함은 자동이 아니다. 이 설계는
거기까지 다루지 않는다.
