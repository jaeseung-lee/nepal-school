# 학교·기관 연락 명부

외부 문의 전에는 프로젝트의 공통 연락 명부를 확인한다. 이메일과 문의 폼을 바꾸거나 발신 계정을 바꿔도 같은 학교·기관에 최초 소개를 반복하지 않는다.

## 저장 위치

- 기준 데이터: `output/outreach/contact-register.json`
- 읽기용 명부: `output/outreach/contact-register.md`
- 엑셀에서 열 수 있는 명부: `output/outreach/contact-register.csv`
- 2026-09-18 오사카 15개교의 원문·발송 기록: `outputs/osaka-nepal-language-schools-2026-09-18/outreach-messages.json`
- 2026-09-18 오사카 개호 채용처 10곳의 원문·발송 기록: `output/outreach/osaka-care-send-log-2026-09-18.json`
- 개호 채용처 발송 결과: `output/outreach/osaka-care-send-results-2026-09-18.md`

연락 명부는 기존 `.gitignore`의 `output/outreach/` 아래에 저장하며, 공개 홈페이지에는 넣지 않는다. 이 로컬 프로젝트를 사용하는 후속 작업에서 공통으로 참고한다. 다른 기기나 다른 프로젝트로 자동 동기화되는 명부는 아니다.

## 이번에 등록한 기록

- 오사카 일본어학교 15곳: 2026-09-18 이메일 발송 11곳, 문의 폼 접수 4곳. 모두 `contacted`이며 동일한 최초 문의 대상에서 제외한다.
- GK학교와 웰학원: 폼으로 접수했지만 시도했던 이메일도 같은 학교의 연락처로 보관한다.
- 기존 개호시설 4곳: 2026-07-27 자료에는 Gmail 초안만 작성했다고 기록되어 있다. 이후 상태는 확인하지 않았으므로 `needs_review`로 구분한다. 현재 발송 완료나 미발송으로 단정하지 않는다.
- 오사카 특정기능1호 개호 채용처 10곳: 2026-09-18 이메일 9곳 발송, 愛の里 공식 문의폼 1곳 접수 완료. 이메일 9건 모두 실제 From `이재승 <lee_js@jeongwoohrd.com>` 및 각 To 헤더를 확인했다. 모두 `contacted`로 최초 문의 재발송 대상에서 제외한다. ヴェローナケア는 폼 확인 화면의 입력 내용이 비어 최종 제출하지 않았고 공식 법인 이메일로 발송했다. 이 실패 이력도 보존한다.
- 기본적으로 학교·기관 단위로 관리한다. 답장에서 확인된 담당자 실명과 다른 이메일은 같은 기관에 추가한다. 답장 확인 상태는 명부의 `reply_status`와 `history`에 기록한다.

## 발송 전 확인

```bash
python3 scripts/check-outreach.py "GK日本語学校" "gk-jpns@gk-jps.osaka.jp"
python3 scripts/check-outreach.py "https://www.osakaeisai.com/contact/"
```

- 종료 코드 `1`: 이미 연락한 대상. 동일한 최초 문의를 다시 보내지 않는다.
- 종료 코드 `2`: 기존 초안, 같은 도메인의 다른 주소, 불명확한 기록, 또는 명부 오류. 기존 이력을 먼저 확인한다.
- 종료 코드 `0`: 입력한 이름·주소와 일치하는 기록을 찾지 못함. 발송 허가나 전수 중복 검증을 의미하지 않는다.

학교명과 연락처를 함께 입력하면 이름·이메일·폼 중 하나가 일치해도 기존 기록을 찾는다. 이메일 대소문자, URL의 `www`, 마지막 `/`, URL 인코딩과 추적 매개변수 차이는 정규화한다. 문의 폼의 `page_id` 같은 의미 있는 매개변수는 보존한다. 같은 도메인이더라도 캠퍼스나 담당 부서가 다를 수 있어 도메인만 일치하면 확인 대상으로 표시한다.

이 도구는 조회 전용이며 메일 서비스의 발송 버튼을 차단하지 않는다. 중복 방지는 `AGENTS.md`의 발송 전 확인 규칙과 함께 적용한다.

## 기록 갱신

새 발송은 전송 전에 `needs_review`로 기록하고 완료 근거가 확인되면 `contacted`로 변경한다. 이전 이력을 지우지 않고 `history`에 추가하며 읽기용 Markdown/CSV도 함께 갱신한다. 사용자가 특정 대상의 후속 연락을 요청하면 기존 항목에 기록한다. 회신이 없다는 이유로 자동 재발송하지 않는다. 수신 거부나 연락 중단 요청을 받으면 해당 요청도 명부에 남기고 이후 발송 대상에서 제외한다.

학교 이름이 비슷해도 별개 캠퍼스는 별도 항목으로 유지한다. 현재 大阪国際アカデミー와 大阪国際アカデミー南キャンパス는 서로 다른 연락처를 가진 별도 항목이다.

## 하루 한 번 학교 답장 확인

Codex의 **오사카 학교 답장 확인** 자동화(`automation-3`)가 이 작업에서 하루에 한 번(24시간마다) `lee_js@jeongwoohrd.com`의 관련 수신 메일을 확인한다. 대상은 위 오사카 15개교이며 기존 개호시설 초안 4곳은 제외한다.

- 새 답장·중요한 변화가 있을 때만 학교명, 담당자, 수신시각, 한국어 요약과 필요한 조치를 알린다. 변화가 없으면 알리지 않는다.
- 확인한 메시지는 `output/outreach/reply-monitor-state.json`에 기록해 중복 알림을 막는다. 읽음 여부로만 새 답장을 판정하지 않는다.
- 메일 커넥터가 다른 계정에 연결되어 있으면 해당 계정에서 대신 확인하지 않는다. 로그인된 회사 Gmail을 브라우저로 확인하고 계정 주소를 검증한다.
- 자동화는 확인·기록·알림만 한다. 사용자의 별도 지시 없이 후속 메일을 보내거나 미팅을 확정하지 않는다.
- JSON 이력을 갱신한 뒤 `python3 scripts/render-outreach-register.py`로 Markdown/CSV도 갱신한다.
