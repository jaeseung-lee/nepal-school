# 페이스북 월간 예약 게시 — 운영 설명서

정우인재개발원 페이스북 페이지에 **한 달치 게시물(사진 1장 + 베트남어·미얀마어·네팔어 본문)을 예약**하는 절차입니다. 한 달에 한 번, 이 문서를 처음부터 끝까지 따라 하면 됩니다.

읽는 사람은 **사업주 한 명**입니다. 코드를 읽을 필요는 없습니다. 모든 명령은 그대로 베껴 쓰면 되고, 명령마다 **눈으로 확인할 것**이 적혀 있습니다. 눈으로 확인하라고 적힌 것은 **기계가 대신 봐 줄 수 없는 것**입니다 — 적힌 대로 보지 않으면 그 보호는 없는 것과 같습니다.

명령은 모두 저장소 폴더(`nepal-school`)에서 터미널을 열고 실행합니다. `2026-11` 자리에는 **그 달**을 적습니다.

> `npm run ...` 뒤의 `--`는 빼지 마세요. 그 뒤의 말을 도구에 넘기라는 표시입니다.

---

## 먼저 — 도구가 깔려 있는지 확인 (처음 한 번만, 그리고 새 맥에서 한 번)

아래 명령은 모두 **터미널**에서 돌립니다. 터미널은 맥에서 `⌘(커맨드)+스페이스`를 누르고 `터미널`이라고 쳐서 엽니다. 창이 열리면 먼저 저장소 폴더로 들어갑니다. 아래 두 줄을 차례로 베껴 넣으세요. 첫 줄의 `~/nepal-school`은 이 폴더가 놓인 자리입니다 — 다른 곳에 두었다면 그 경로로 바꿔 적습니다.

```
cd ~/nepal-school
pwd
```

`pwd`가 `.../nepal-school`을 찍으면 맞게 들어온 것입니다. **모든 명령은 이 폴더에서 돌립니다.**

이 도구는 두 가지가 깔려 있어야 돌아갑니다. 각각 아래 명령으로 확인합니다.

```
uv --version
node --version
```

- 둘 다 **숫자(버전)가 찍히면** 준비가 끝났습니다. 다음 절로 가세요.
- `uv: command not found`(또는 `command not found: uv`)가 나오면 `uv`가 없는 것입니다. `uv`는 이 도구가 쓰는 파이썬과 부품을 알아서 받아 오는 프로그램입니다. 아래 한 줄을 그대로 붙여넣어 설치하고, **터미널 창을 닫고 새로 연 뒤** `uv --version`을 다시 확인하세요.

  ```
  curl -LsSf https://astral.sh/uv/install.sh | sh
  ```

- `node: command not found`가 나오면 [nodejs.org](https://nodejs.org)에서 LTS 설치본을 받아 설치한 뒤 터미널을 새로 열고 `node --version`을 다시 확인하세요. `npm`은 Node와 함께 깔립니다.

**처음 한 번은 명령이 몇 분 걸릴 수 있습니다.** `uv`가 파이썬과 부품을 받아 오기 때문입니다. 화면이 멈춘 것처럼 보여도 기다리세요. 두 번째부터는 곧바로 돕니다.

`uv`가 없는 채로 명령을 돌리면 터미널에 `npm ERR! code 127`이 보입니다. **127은 "그런 명령이 없다"는 뜻**이므로, 그때는 이 절로 돌아와 `uv --version`부터 다시 확인하세요.

## 0. 한 달의 흐름 (한눈에)

| 순서 | 하는 일 | 명령 |
| --- | --- | --- |
| 1 | 토큰이 살아 있는지 본다 | `npm run fb:check-token -- --month 2026-11` |
| 2 | 플랜(한 달치 글)을 만든다 | Claude Code 세션에 맡긴다 |
| 3 | 이미지 프롬프트를 뽑는다 | `npm run fb:images -- --month 2026-11` |
| 4 | 그림을 만들어 폴더에 넣는다 | 그림 도구 + 손으로 저장 |
| 5 | 역번역 워크시트를 만든다 | `npm run fb:backtranslate-template -- --month 2026-11` |
| 6 | 되번역을 채운다 | **별도** Claude Code 세션에 맡긴다 |
| 7 | 검사한다 | `npm run fb:validate -- --month 2026-11` |
| 8 | 검토 화면을 읽는다 (**뜻을 확인하는 유일한 지점**) | `npm run fb:review -- --month 2026-11` |
| 9 | 연습으로 돌려 본다 | `npm run fb:schedule -- --month 2026-11` |
| 10 | 실제로 예약한다 | `npm run fb:schedule -- --month 2026-11 --confirm` |
| 11 | 페이스북에서 눈으로 확인한다 | 페이지 → 예약된 게시물 |

**첫 실제 월에는 9번과 10번 사이에 「6. 첫 실제 월 전에 꼭 해야 할 일」을 먼저 끝내야 합니다.**

한 달의 파일은 모두 `output/facebook/2026-11/` 한 폴더에 모입니다.

| 파일·폴더 | 무엇인가 | 누가 만드는가 |
| --- | --- | --- |
| `plan.json` | 그 달의 게시물 전부(한국어 원문, 현지어 본문, 날짜, 그림 이름) | Claude Code 세션 |
| `images/` | 게시물마다 사진 1장 | 사업주(그림 도구로 만들어 저장) |
| `backtranslation.json` | 되번역 워크시트 | 5번 명령이 빈 틀을 만들고, 별도 세션이 채운다 |
| `review.html` | 사람이 읽는 검토 화면 | 8번 명령 |
| `scheduled.json` | 무엇을 올렸는지 적은 **원장** | 10번 명령(필요하면 손으로 고친다) |
| `scheduled.json.lock` | 빈 파일. 두 실행이 같은 원장을 동시에 쓰지 못하게 막는 표시입니다. **무시하세요** — 열어 볼 것도, 지울 것도 없습니다(연습 실행도 이 파일을 만듭니다). | 9·10번 명령 |

## 1. 최초 1회 준비 (한 번만)

### 1-1. 페이지를 비즈니스 포트폴리오에 넣고 토큰을 발급한다

1. [business.facebook.com](https://business.facebook.com)에서 **비즈니스 포트폴리오**를 만들거나 엽니다.
2. **비즈니스 설정 → 계정 → 페이지**에서 정우인재개발원 페이지를 추가합니다.
3. **비즈니스 설정 → 사용자 → 시스템 사용자**에서 시스템 사용자를 하나 만듭니다(예: `facebook-posting`). 역할은 관리자가 아니어도 됩니다.
4. 그 시스템 사용자에게 **자산 추가 → 페이지 → 정우인재개발원**을 주고 **콘텐츠 관리** 권한을 켭니다.
5. **토큰 생성**을 눌러 아래 세 권한을 선택합니다. (이 이름 그대로 고르면 됩니다.)
   - `pages_manage_posts`
   - `pages_read_engagement`
   - `pages_show_list`
6. 나온 토큰을 복사합니다. **시스템 사용자 토큰은 만료가 없습니다** — 그래서 이 방법을 씁니다.

**잘 안 되면(폴백):** 비즈니스 포트폴리오를 쓸 수 없는 상황이면 [개발자 도구의 그래프 API 탐색기](https://developers.facebook.com/tools/explorer/)에서 위 세 권한으로 **페이지 액세스 토큰**을 받고, **액세스 토큰 디버거**에서 `Extend Access Token`을 눌러 장기 토큰으로 바꿉니다. 이 토큰은 약 60일마다 다시 발급해야 하므로, 달마다 1번 명령(`fb:check-token`)이 더 중요해집니다.

### 1-2. 토큰을 `.env`에 적는다

저장소 맨 위 폴더에 `.env` 파일을 만들고 한 줄을 적습니다.

```
FB_PAGE_TOKEN=여기에_복사한_토큰
```

- **이 파일은 UTF-8로 저장하고, 한국어 주석을 넣지 마세요.** 위의 한 줄만 있으면 됩니다. 편집기가 한국어를 다른 인코딩(EUC-KR)으로 저장하면 도구가 `.env`를 읽지 못해 **한국어 안내와 함께 멈춥니다** — 그때는 편집기에서 인코딩을 UTF-8로 바꿔 다시 저장하면 됩니다.
- 이 파일은 **절대 커밋하지 않습니다**(이미 무시 목록에 있습니다). 남에게 보내지도 마세요.
- 터미널에 `export FB_PAGE_TOKEN=...`을 쳐 둔 적이 있으면 지우세요(`unset FB_PAGE_TOKEN`). 두 곳에 서로 다른 값이 있으면 도구가 어느 쪽이 새 토큰인지 알 수 없어 **일부러 멈춥니다**.
- 토큰은 화면·기록·파일 어디에도 찍히지 않습니다. 오류 메시지에 나올 자리에는 `***`로 가려집니다.

### 1-3. 페이지 소개란에 상담 언어를 적는다

페이스북 페이지 → **정보 수정**에서 소개란에 **베트남어·미얀마어·네팔어**로 상담이 가능하다는 것을 적습니다. 게시물이 세 언어로 나가는데 소개란이 한국어뿐이면, 글을 읽고 찾아온 사람이 자기 말로 물어도 되는지 알 수 없습니다.

### 1-4. 토큰을 점검한다

```
npm run fb:check-token -- --month 2026-11
```

**눈으로 확인할 것:** 페이지 이름이 `정우인재개발원`으로 나오는지.

이 검사가 증명하는 것은 **하나뿐입니다: 이 토큰으로 페이지를 읽을 수 있다.** 글을 올릴 수 있는지는 증명하지 않습니다(권한 목록을 조회하지 않습니다). 올릴 수 있다는 증거는 「6. 첫 실제 월 전에 꼭 해야 할 일」의 테스트 예약뿐입니다.

## 2. 매달 하는 일

### 단계 1 — 토큰 점검

```
npm run fb:check-token -- --month 2026-11
```

**눈으로:** 페이지 이름이 맞는지. 토큰이 만료되었다고 나오면 1-1을 다시 하고 `.env`를 고칩니다. 이 단계를 맨 앞에 두는 까닭은, 한 달치를 다 준비한 뒤에 토큰 문제를 발견하지 않으려는 것입니다.

### 단계 2 — 플랜 만들기 (Claude Code 세션)

폴더를 만듭니다.

```
mkdir -p output/facebook/2026-11/images
```

Claude Code 세션을 열고 **아래 「플랜 작성 지침」을 그대로 붙여넣습니다.** 세션이 `output/facebook/2026-11/plan.json`을 만듭니다.

**눈으로:** 게시물 수가 **3의 배수**인지(한 소재 = 베트남어·미얀마어·네팔어 3건), 날짜가 **하루에 한 건씩** 이어지는지, 한국어 원문이 사실과 맞는지.

#### 플랜 작성 지침 (세션에 붙여넣는 글)

> `output/facebook/2026-11/plan.json`에 2026년 11월 한 달치 페이스북 게시물 플랜을 만들어 주세요. 형식과 규칙은 `scripts/facebook/plan_model.py`와 `scripts/facebook/README.md`에 있습니다. 아래는 반드시 지킬 것입니다.
>
> 1. **소재 하나에 게시물 3건**(베트남어 `vi` → 미얀마어 `my` → 네팔어 `ne` 순서). 한 소재의 3건은 번호가 이어지고 날짜도 사흘 연속이어야 합니다. 한 달이면 열 소재 30건입니다.
> 2. **한국어 원문(`source_ko`)이 먼저이고, 현지어 본문(`body_local`)은 그 번역**입니다. 한 소재의 3건은 `source_ko`가 글자까지 같아야 합니다.
> 3. **모든 원문과 본문은 승인된 상담 문구(용어집의 `cta`)로 끝납니다.** 한 글자도 바꾸지 마세요.
> 4. **`output/facebook/facts.json`에 없는 수치는 쓸 수 없습니다.** 쓴 사실의 키를 `fact_keys`에 적습니다. 유학생 시간제취업 허용 시간(흔히 말하는 "주 20시간")처럼 1차 출처를 찾지 못해 일부러 비워 둔 수치는 **본문에 쓰지 마세요.**
> 5. **수는 숫자로 적고 단위를 바꾸지 마세요.** 원문이 `6,800,000원`이면 본문도 `6,800,000`처럼 숫자로 적습니다. `1년치`를 `cả năm`처럼 말로 풀어 쓰거나 `680만 원`으로 단위를 바꾸면, 나중에 되번역 대조에서 **거짓 오류**가 납니다. 베트남어 금액은 현지 관행대로 점(`6.800.000`)으로 적어도 됩니다.
> 6. **`fact_keys`와 `university_names`는 비어 있어도 `[]`로 반드시 적습니다.** 키가 없으면 플랜을 읽는 쪽이 거부합니다.
> 7. **게시물은 무료 상담 안내까지만 말합니다.** 합격·취업·비자 보장, 비용 약속, 대학과의 협력·제휴 관계, 상담 이후의 절차나 수수료는 쓰지 않습니다. 금지 표현 목록은 `scripts/facebook/data/banned-phrases.json`에 있습니다.
> 8. 대학 실명은 `output/facebook/universities.json`에 있는 이름만, **소개하는 맥락에서만** 씁니다.
> 9. **이미지 프롬프트(`image_prompt`)는 영어로 쓰고, 아래 두 문구를 글자 그대로 넣습니다.**
>    - `no text, no letters, no logos`
>    - `no real people, no real campuses, no company facilities`
>
>    (글자를 금지하는 까닭: 그림 도구가 미얀마 문자·데바나가리를 깨뜨려 그립니다. 실존 인물·실제 캠퍼스·회사 시설을 금지하는 까닭: AI 그림이 실제 기록 사진으로 읽히면 안 됩니다.)
> 10. 다 만든 뒤 `npm run fb:validate -- --month 2026-11`을 돌려 보세요. **이 단계에서 멈추는 조건은 "오류 0건"이 아니라 "남은 오류가 `이미지없음`뿐"입니다.** 그림은 아직 없으므로 게시물마다 `이미지없음` 오류가 하나씩 나는 것이 정상입니다(그림은 뒤의 단계 3·4에서 넣습니다). 그 밖의 오류는 전부 고쳐 주세요 — 특히 `이미지경로`·`이미지확장자`·`이미지중복`은 **그림이 아니라 플랜의 파일 이름 문제**이므로 여기서 고쳐야 합니다. `이미지없음`을 없애려고 `image_file`이나 게시물 수를 고치지 마세요. 이 단계에서는 `validate`가 늘 종료 코드 1로 끝나므로 터미널이 `npm ERR! code 1` 덩어리를 함께 찍습니다 — **그 단계에서는 정상이고**, 고장이 아닙니다.

### 단계 3 — 이미지 프롬프트 뽑기

```
npm run fb:images -- --month 2026-11
```

게시물마다 **저장할 파일 이름**과 **프롬프트**가 나옵니다.

**눈으로:** 프롬프트마다 위의 두 금지 문구가 그대로 들어 있는지(명령이 맨 위에 다시 적어 줍니다).

### 단계 4 — 그림 만들어 넣기

프롬프트를 하나씩 그림 도구(ChatGPT 등)에 붙여넣고, 받은 그림을 **적힌 파일 이름 그대로** `output/facebook/2026-11/images/`에 저장합니다.

**눈으로(그림 한 장마다):**
- 글자가 보이지 않는지. 한 글자라도 보이면 다시 만듭니다(현지어 글자는 거의 반드시 깨집니다).
- 실제 인물 사진·특정 대학 캠퍼스·회사 시설처럼 보이지 않는지.
- `.png` 또는 `.jpg`이고 8MB 이하인지.

### 단계 5 — 역번역 워크시트 만들기

```
npm run fb:backtranslate-template -- --month 2026-11
```

`output/facebook/2026-11/backtranslation.json`에 빈 워크시트가 생깁니다. **이미 있으면 덮어쓰지 않고 멈춥니다**(채워 둔 되번역이 사라지지 않게). 플랜을 고쳐서 다시 만들어야 하면 그 파일을 다른 이름으로 옮기거나 지운 뒤 실행합니다.

### 단계 6 — 되번역 채우기 (별도 Claude Code 세션)

**새 세션**을 엽니다. 이 세션에 **한국어 원문을 보여 주지 마세요.** 원문을 보면 베끼기만 하고 되번역이 아니게 되어, 다음 단계의 대조가 아무것도 걸러 내지 못합니다.

세션에 붙여넣는 글:

> `output/facebook/2026-11/backtranslation.json`을 열어 항목마다 `body_local`(베트남어·미얀마어·네팔어 본문)을 **한국어로 되번역**해 `back_ko`에 적어 주세요. 다른 파일은 열지 마세요 — 특히 `plan.json`을 보면 안 됩니다.
>
> - **주어를 빼지 마세요.** 현지어 문장이 주어를 생략해도(미얀마어·네팔어는 흔히 생략합니다) 한국어 되번역에는 그 문장의 주어를 적습니다. 문장이 "우리가 ○○와 협약을 맺었다"는 뜻이면 `저희는 ○○와 협약을 맺었습니다`라고 쓰고, 주어가 대학이면 그 대학 이름을 씁니다.
> - **수는 숫자로, 원문과 같은 단위로** 적습니다. `이십 시간`이 아니라 `20시간`입니다. 베트남어 본문의 점 천단위(`6.800.000`)는 되번역에서 **쉼표**로 적습니다(`6,800,000`).
> - 항목의 `index`와 `language`를 보고 **그 항목에 맞는 되번역**을 적습니다. 번호를 바꿔 넣으면 기계가 못 잡습니다.
> - `month`와 `body_hash` 같은 다른 값은 건드리지 마세요.

**눈으로:** 항목 수가 게시물 수와 같은지, 빈 칸이 없는지.

> **이 워크시트를 손으로 새로 만들지 마세요.** 단계 5가 만든 파일을 채우는 것만 합니다. 그 파일에는 그 달 표시와 본문 지문이 들어 있어, 채운 뒤에 본문을 고치면 다음 단계가 알아챕니다. 손으로 만든 파일에는 그 표시가 없어 **낡은 되번역이 조용히 통과합니다.**

### 단계 7 — 검사

```
npm run fb:validate -- --month 2026-11
```

**오류 0건이 될 때까지** 고치고 다시 돌립니다. 오류가 하나라도 남으면 예약은 시작되지 않습니다.

**경고는 막지 않습니다.** 특히 `역번역중복` 경고는 **흠 없는 한 달에도 소재마다 2건, 한 달에 스무 건쯤 납니다** — 한 소재의 세 한국어 원문이 같으니 세 되번역이 모두 충실하면 똑같아지는 것이 오히려 정상입니다. 되번역이 정확할수록 더 많이 납니다. 끄지 않는 까닭은, 나쁜 본문 위에 다른 게시물의 좋은 되번역을 복사한 가장 위험한 경우가 바로 이 모양이기 때문입니다. 확인하는 방법은 하나입니다: 그 게시물의 **현지어 본문만** 새 세션에서 다시 되번역해 같게 나오는지 봅니다.

자주 나오는 오류 두 가지:
- `역번역수치` — 숫자가 원문과 다릅니다. 대개 되번역이 숫자를 말로 풀었거나 베트남어의 점 천단위를 그대로 옮긴 것입니다. 되번역을 고칩니다. 본문이 숫자를 말로 썼다면 **본문**을 고칩니다.
- `역번역금지표현` — 되번역에 금지 문구가 보입니다. 현지어 본문이 정말 그렇게 말하거나, 되번역이 본문을 잘못 옮긴 것입니다. 어느 쪽인지는 그 본문만 새 세션에서 다시 되번역해 보면 압니다.

### 단계 8 — 검토 화면 읽기 (**뜻을 확인하는 유일한 지점**)

```
npm run fb:review -- --month 2026-11
open output/facebook/2026-11/review.html
```

**이 화면은 만든 이 맥에서 열어야 합니다.** 시스템에 깔린 글꼴만 쓰기 때문에 다른 컴퓨터(특히 리눅스)에서는 미얀마 글자가 네모로 보일 수 있습니다. **읽을 수 없는 화면은 검사가 꺼진 것과 같습니다.**

게시물마다 세 단이 있습니다: **한국어 원문 · 되번역 · 현지어 본문**. 앞의 두 단을 나란히 읽는 것이 이 일의 핵심입니다.

화면의 표시는 세 모양입니다. **세 모양은 낱말이 어떻게 다른지만 말하고, 뜻이 바뀌었는지는 말하지 않습니다.**

- **파란 막대** = 되번역에만 있는 말. 원문에 없는 약속이 들어온 자리일 수 있습니다.
- **붉은 막대** = 원문에만 있는 말. 한정어가 사라진 자리일 수 있습니다(`평균`·`1년치`·`다를 수 있습니다`가 빠졌는지).
- **노란색** = 양쪽에 말이 있는데 서로 다른 말.

**노란색을 건너뛰지 마세요.** 뜻을 바꾸는 변경은 세 모양 **어느 것으로도** 나타납니다. 이 일에서 가장 무서운 변경인 부정 뒤집힘이 바로 그렇습니다 — **부정이 뒤집히면 노란색**으로 나타나는 일이 많습니다: `보장하지 않습니다` → `보장합니다`처럼 `-지 않`이 떨어지거나 `있`과 `없`이 뒤바뀌면 노란색입니다(`안`·`못`이 덧붙으면 파란 막대, 빠지면 붉은 막대). 글자 차이 숫자로도 걸러지지 않습니다 — 「3-1」에서 재 보니 부정 뒤집힘은 **0.05**로, 멀쩡한 의역(0.08~0.12)보다 **작습니다.**

그래서 **표시된 곳은 모양을 가리지 말고 모두 읽으세요.** 막대가 먼저 눈에 들어오는 것은 색이 선명해서일 뿐, 뜻이 거기 있어서가 아닙니다.

**눈으로 볼 것(표시된 곳마다):**
- 부정이 뒤집히지 않았는지(`보장합니다` ↔ `보장하지 않습니다`, `있습니다` ↔ `없습니다`).
- 숫자(금액·기간·시간·인원)가 두 단에서 같은지.
- 원문에 없는 약속·보장·조건이 덧붙지 않았는지.
- 원문에 있던 한정어(`평균`, `~일 수 있습니다`)가 빠지지 않았는지.
- 사진이 글과 맞는지, 사진에 글자가 없는지.

**게시물당 강조 칩이 몇 개씩 있는 것은 정상입니다.** 충실한 의역도 글의 27~33%가 칠해지고 칩이 3~4개 생깁니다. 칩이 있다는 것 자체가 문제의 신호는 아닙니다 — 그래도 **칩 하나하나를 읽어** 뜻이 같은지 사람이 판단해야 합니다. 한 글자짜리 표시 하나가 문장의 뜻을 뒤집을 수 있습니다.

### 단계 9 — 연습 실행

```
npm run fb:schedule -- --month 2026-11
```

페이스북에 **아무것도 보내지 않고** 원장도 건드리지 않습니다. 몇 건이 나갈 예정인지, 걸리는 것이 없는지만 보여 줍니다. (달 폴더에 `scheduled.json.lock`이라는 빈 파일이 생깁니다 — 두 실행이 겹치지 않게 막는 표시이니 무시하세요.)

**눈으로:** `예약 예정: 30건`처럼 건수가 맞는지. 날짜와 그림 이름이 게시물마다 맞는지.

### 단계 10 — 실제 예약

```
npm run fb:schedule -- --month 2026-11 --confirm
```

`--confirm`이 있어야 실제로 올라갑니다. 끝나면 네 가지 숫자가 나옵니다.

```
예약: 28건
이미 예약돼 건너뜀: 1건
결과 불명: 1건  ← 성공도 실패도 아닙니다. 페이스북에서 사람이 확인해야 합니다.
실패: 0건
```

- **예약** — 이번에 올라간 건.
- **이미 예약돼 건너뜀** — 지난 실행에서 이미 올린 건(원장에 적혀 있어 다시 올리지 않습니다).
- **결과 불명** — 요청은 나갔는데 답을 받지 못한 건. **예약이 만들어졌을 수도, 아닐 수도 있습니다.** → 「5-1」을 보세요.
- **실패** — **페이스북이 거절했거나, 보내기 전 검사(예약 시각·그림)에서 걸러진 건.** 어느 쪽이든 아무것도 만들어지지 않았으므로, 까닭을 고치고 다시 돌리면 그 건만 다시 시도합니다.
  - 까닭이 **예약 시각**에 대한 말이면(`너무 가깝습니다`·`너무 멉니다`·`이미 지난 시각`) 고칠 곳은 **플랜의 날짜**입니다. 예약은 지금부터 10분 뒤 ~ 75일 뒤 사이만 됩니다. 이 경우는 검사(단계 7)를 통과한 플랜에서도 납니다 — 검사는 날짜가 그 달 안에 있는지만 보고, 지금 시각과의 거리는 예약할 때 처음 보기 때문입니다. 종료 코드가 2로 끝나도 **개발자에게 보낼 일이 아닙니다.**
  - 까닭이 **그림**에 대한 말이면 그 파일을 다시 저장하고(단계 4) 다시 돌립니다.

같은 까닭으로 여러 건이 실패하면 **까닭은 한 번만** 적고 게시물 번호를 함께 보여 줍니다.

### 단계 11 — 페이스북에서 눈으로 확인

페이스북 페이지 → **예약된 게시물** 목록을 엽니다.

**눈으로:** 건수가 위의 `예약`+`건너뜀` 합과 같은지, 날짜가 하루에 하나씩인지, 사진과 본문이 맞는지. 이 도구는 페이스북이 준 답만 알 뿐, 화면에 실제로 보이는지는 모릅니다.

## 3. 이 도구가 **못 하는 것** (반드시 읽기)

여기 적힌 다섯 가지는 고장이 아니라 **알려진 한계**입니다. 이것을 모르고 쓰면, 기계가 봐 주고 있다고 믿는 자리에 사실은 아무것도 없습니다.

### 3-1. 되번역의 숫자(글자 차이)는 **뜻을 보지 못합니다**

검토 화면에 `원문과 글자 차이 0.12`처럼 나오는 숫자는 **글자가 얼마나 다른지**일 뿐입니다. 실제로 재 본 값입니다(다섯 문장짜리 글 기준).

| 무엇을 바꿨는가 | 글자 차이 |
| --- | --- |
| 부정을 뒤집음 (`입니다` → `이 아닙니다`) | **0.05** |
| 금액을 바꿈 | **0.01** |
| 없는 약속 한 문장을 덧붙임 | **0.12** |
| (잘못된 것이 없는) 충실한 의역 | **0.08 ~ 0.12** |

보시는 대로 **뜻을 망친 세 가지가 멀쩡한 의역보다 오히려 작거나 같습니다.** 그래서 **어떤 임계값으로도 이 둘을 가를 수 없습니다.** 숫자가 작다고 안심할 수 없고, 커도 틀렸다는 뜻이 아닙니다.

**뜻은 검토 화면의 세 단을 사람이 읽어야만 확인됩니다.** 단계 8을 건너뛰면 뜻을 보는 장치는 이 시스템에 **하나도** 없습니다.

### 3-2. 현지어 금지 표현 목록은 **아직 원어민 검수를 받지 않았습니다**

`scripts/facebook/data/banned-phrases.json`의 베트남어·미얀마어·네팔어 문구와 "저희·우리" 같은 1인칭 판정에 쓰는 낱말은 **AI가 작성한 것**이고, 사람이 확인한 것은 **한국어 목록뿐**입니다. **첫 실제 월 전에 세 언어 원어민의 검수가 필요합니다**(「6-1」).

그래서 되번역에 **검수된 한국어 목록을 한 번 더 겹쳐** 걸고 있습니다. 세 현지어 본문에 걸리는 기계 검사는 **이것 하나뿐**입니다. 다만 **목록에 적힌 표현만** 잡습니다 — 목록에 없는 약속은 여전히 사람의 눈뿐입니다.

### 3-3. 1차 출처를 못 찾은 수치는 **쓸 수 없습니다**

흔히 말하는 "유학생은 주 20시간 일할 수 있다" 같은 수치는 1차 출처를 확인하지 못해 `output/facebook/facts.json`에 **일부러 넣지 않았습니다**. 허용 시간은 학위과정·한국어 급수·성적·학기/방학에 따라 달라지므로 숫자 하나만 현지어로 내보내면 읽는 사람이 자기 조건과 무관하게 받아들입니다. 플랜에 그 숫자를 쓰면 검사에서 막힙니다 — 막히는 것이 맞습니다.

### 3-4. 되번역에 **주어가 없으면** 대학 관련 금지 검사가 통째로 놓칩니다

대학 실명이 나오는 게시물에서만 거는 문구가 **여덟**입니다: `협력`·`협약`·`제휴`·`MOU`·`파트너`·`연계`·`알선`·`합격 가능`. 이 여덟은 **회사가 스스로 말하는 문장**에서만 잡습니다(대학 자신의 이야기인 `산학협력단`·`국제협력처`까지 막으면 대학 소개 글이 전부 걸리기 때문입니다). 그래서 되번역에 주어가 없으면 **이 여덟 문구 전부가 하나도 걸리지 않습니다**(실제로 재 봤습니다: 8개 중 0개).

미얀마어·네팔어는 주어를 자주 생략하고 되번역은 AI가 하므로, 사람이 쓴 한국어 원문과 달리 **되번역 쪽에서 주어가 떨어져 나갑니다.** 워크시트에도 "주어를 적으라"는 지침이 들어 있지만 **기계로 강제되지 않습니다.** 단계 6에서 반드시 일러 주세요.

주어가 없어도 잡히는 것은 이것뿐입니다: 명사구 `협력 대학`·`제휴 대학`·`협약 대학`·`파트너 대학`, 그리고 노골적인 약속 `합격 보장`·`취업 보장`·`입학을 도와`·`무료 유학`.

### 3-5. 오류 메시지에 실린 문장이 끝에서 깨져 보일 수 있습니다

금지 표현 오류는 문제가 된 문장을 짧게 잘라 보여 줍니다. 자르는 자리를 글자 수가 아니라 내부 단위로 세기 때문에, 미얀마 문자·데바나가리나 일부 한글이 섞이면 **끝 글자가 깨져 보일 수 있습니다.** 판정에는 영향이 없습니다 — 메시지의 글자 모양만 어색해집니다.

## 4. 원장(`scheduled.json`) 손으로 고치기

원장은 **무엇을 이미 올렸는지** 적어 둔 파일입니다. 이것 덕분에 중간에 끊긴 뒤 다시 돌려도 같은 사진이 두 번 나가지 않습니다. 줄 하나가 게시물 하나입니다.

```json
{
  "0": {"결과": "61595913932801_122100000000000001", "이미지": "00-visa-d2-vi.png"},
  "1": {"결과": "결과 불명", "이미지": "01-visa-d2-my.png"},
  "2": {"결과": "61595913932801_122100000000000003", "이미지": "02-visa-d2-ne.png"}
}
```

- `"0"` — 게시물 번호.
- `"결과"` — 페이스북이 준 사진 번호, 또는 `"결과 불명"`.
- `"이미지"` — 그 줄이 어느 게시물인지 알아보는 표시. **고치지 마세요.**

**손으로 하는 편집은 두 가지뿐입니다.** 아래 예를 그대로 베끼는 쪽이 설명을 따르는 것보다 정확합니다.

### 편집 ① `"결과 불명"`을 `"확인함"`으로 바꾸기

페이스북에 그 게시물이 **있는 것을 눈으로 본** 다음에만 합니다.

**고치기 전** (파일 전체)

```json
{
  "0": {"결과": "61595913932801_122100000000000001", "이미지": "00-visa-d2-vi.png"},
  "1": {"결과": "결과 불명", "이미지": "01-visa-d2-my.png"},
  "2": {"결과": "61595913932801_122100000000000003", "이미지": "02-visa-d2-ne.png"}
}
```

**고친 뒤** (파일 전체 — `결과 불명` 넉 글자만 `확인함`으로 바꿨습니다)

```json
{
  "0": {"결과": "61595913932801_122100000000000001", "이미지": "00-visa-d2-vi.png"},
  "1": {"결과": "확인함", "이미지": "01-visa-d2-my.png"},
  "2": {"결과": "61595913932801_122100000000000003", "이미지": "02-visa-d2-ne.png"}
}
```

줄을 지우지 않고 **표시해 두는** 까닭: 어떤 값이든 들어 있으면 다시 올리지 않으므로, `확인함`은 "보고 확인했다"와 "아직 안 봤다"를 가르는 표시가 됩니다.

### 편집 ② 줄 하나를 지우기

페이스북에 그 게시물이 **없는 것을 눈으로 본** 다음에만 합니다. 지우면 다음 실행에서 그 게시물이 새로 예약됩니다.

**고치기 전** (파일 전체)

```json
{
  "0": {"결과": "61595913932801_122100000000000001", "이미지": "00-visa-d2-vi.png"},
  "1": {"결과": "결과 불명", "이미지": "01-visa-d2-my.png"},
  "2": {"결과": "61595913932801_122100000000000003", "이미지": "02-visa-d2-ne.png"}
}
```

**고친 뒤** (파일 전체 — `"1"` 줄을 통째로 지웠습니다)

```json
{
  "0": {"결과": "61595913932801_122100000000000001", "이미지": "00-visa-d2-vi.png"},
  "2": {"결과": "61595913932801_122100000000000003", "이미지": "02-visa-d2-ne.png"}
}
```

**맨 끝 줄을 지우는 경우**는 앞 줄 끝에 쉼표가 남습니다. 이 도구는 **맨 끝의 쉼표 하나는 받아 줍니다**, 그래서 아래처럼 두어도 됩니다(지우면 더 깔끔합니다).

**고치기 전** (파일 전체)

```json
{
  "0": {"결과": "61595913932801_122100000000000001", "이미지": "00-visa-d2-vi.png"},
  "1": {"결과": "61595913932801_122100000000000002", "이미지": "01-visa-d2-my.png"},
  "2": {"결과": "결과 불명", "이미지": "02-visa-d2-ne.png"}
}
```

**고친 뒤** (파일 전체 — 맨 끝 `"2"` 줄을 지우고 남은 쉼표를 그대로 둔 모양)

```json
{
  "0": {"결과": "61595913932801_122100000000000001", "이미지": "00-visa-d2-vi.png"},
  "1": {"결과": "61595913932801_122100000000000002", "이미지": "01-visa-d2-my.png"},
}
```

> 쉼표 **하나**까지만 받아 줍니다. 줄을 여러 개 지우면서 쉼표가 둘 이상 남거나 괄호를 지우면 파일을 읽지 못해 멈춥니다. 그때는 위의 모양대로 다시 적으면 됩니다.

## 5. 일이 어긋났을 때

### 5-1. `결과 불명`이 보인다

요청은 나갔는데 답을 받지 못한 것입니다. **예약이 만들어졌을 수도 있고 아닐 수도 있습니다.** 그 줄은 요청을 보내기 **직전에** 미리 적어 두기 때문에, 전원이 꺼지거나 창을 닫아도 남습니다.

1. 페이스북 페이지 → **예약된 게시물** 목록을 엽니다.
2. 그 번호의 게시물(날짜와 사진으로 찾습니다)이 **있으면** → 원장에서 그 줄의 `"결과"`를 `"확인함"`으로 바꿉니다(**편집 ①**).
3. **없으면** → 그 줄을 지웁니다(**편집 ②**). 다음 실행에서 새로 예약됩니다.
4. `npm run fb:schedule -- --month 2026-11 --confirm`을 다시 돌립니다.

**확인하지 않고 그냥 두면** 그 게시물은 영구히 빠집니다. **확인하지 않고 줄을 지우면** 같은 사진이 같은 날 두 번 나갑니다. 둘 다 눈으로 보는 것 하나로 막힙니다.

### 5-2. 예상하지 못한 오류로 멈췄다 (또는 Ctrl-C로 끊었다)

화면이 "예약 중에 예상하지 못한 오류가 나 멈췄습니다"라고 말하고, 원장에 `결과 불명`으로 적힌 줄이 남아 있을 수 있습니다. **5-1과 똑같이** 하면 됩니다. 메시지 전체를 복사해 개발자에게 보여 주세요.

### 5-3. 일부만 예약한 뒤 플랜을 고쳐야 한다

- **아직 예약하지 않은 게시물**을 고치는 것은 괜찮습니다. 그냥 고치고 다시 돌리면 됩니다.
- **게시물을 넣거나 빼서 번호가 밀리면** 도구가 알아채고 **아무것도 올리지 않고 멈춥니다**(원장의 `"이미지"` 표시와 어긋나기 때문입니다). 메시지가 어느 줄이 어긋났는지, 무엇을 해야 하는지 말해 줍니다.
- **이미 예약한 게시물의 본문이나 시각만 고치는 경우는 도구가 알아채지 못합니다.** 그림 파일 이름이 그대로이기 때문입니다. 고친 내용은 나가지 않고 페이스북에는 **옛 내용이 예약된 채 남으며**, 화면에는 정상으로 보고됩니다. **이 시스템에서 조용히 어긋나는 자리는 여기 하나뿐입니다.**

  → 예약한 게시물의 본문이나 시각을 고치려면 **페이스북의 그 예약 게시물과 `scheduled.json`의 그 줄을 둘 다 지운 뒤** 다시 돌리세요.

### 5-4. "플랜에 없는 원장 줄 N개"가 보인다

플랜에서 게시물을 지웠지만 **그 게시물은 페이스북에 여전히 예약되어 있습니다.** 플랜에서 지우는 것으로 예약이 취소되지는 않습니다. 내보내지 않으려면 페이스북 페이지의 **예약된 게시물**에서 직접 지우세요.

### 5-5. "다른 예약 실행이 같은 원장을 쓰고 있어 아무것도 올리지 않고 멈춥니다"

다른 터미널 창에서 같은 달을 돌리고 있습니다. **새 창에서 다시 돌리지 마세요** — 두 실행이 같은 원장을 읽으면 같은 사진이 두 번 나갑니다. 멈춘 것처럼 보여도 사진 한 장 올리는 데 최대 1분이 걸립니다. 먼저 돌던 창이 끝나기를 기다리세요.

### 5-6. 도구 자체가 고장 난 것 같다

```
npm run test:facebook
```

1000건이 넘는 자체 검사가 돌아갑니다. 전부 통과하면 도구는 멀쩡하고 입력(플랜·그림·되번역) 쪽 문제입니다. 하나라도 실패하면 **그 출력을 그대로 개발자에게 보여 주고 예약은 하지 마세요.**

## 6. 첫 실제 월 전에 꼭 해야 할 일

아래 두 가지는 **첫 실제 월 게시물을 내보내기 전에** 끝내야 합니다. 둘 다 사람만 할 수 있는 일입니다.

### 6-1. 베트남어·미얀마어·네팔어 금지 문구를 원어민에게 검수받는다

`scripts/facebook/data/banned-phrases.json`을 각 언어 원어민 한 명씩에게 보여 주고 아래를 물어봅니다.

1. 이 문구들이 **실제로 쓰는 말**인가? (어법·표기가 자연스러운가)
2. 같은 뜻을 흔히 쓰는 **다른 표현**이 있는가? (있으면 목록에 더해야 합니다)
3. 이 문구가 **멀쩡한 글까지 막지는** 않는가?

특히 미얀마어·네팔어의 표기 변이(예: 네팔어 `निःशुल्क` / `नि:शुल्क`)를 확인받으세요. 검수 결과를 받으면 파일을 고치고 `npm run test:facebook`을 돌립니다. 검수 전까지는 **현지어 쪽 금지 검사가 충분하다고 가정하지 마세요.**

### 6-2. 테스트 예약 1건을 올려 보고, 눈으로 확인한 뒤 지운다

**이것이 "이 토큰으로 글을 올릴 수 있다"는 유일한 증명입니다.** 토큰 점검(단계 1)은 **읽을 수 있다**만 증명합니다. 토큰을 새로 발급한 달에는 다시 하세요.

**명령 둘로 끝납니다. 손으로 만들 파일은 없습니다** — 본문과 그림은 저장소가 들고 있고, 달 폴더도 원장도 쓰지 않습니다.

1. 올립니다.

   ```
   npm run fb:test-post
   ```

   화면에 **사진 id**와 예약 시각(지금부터 30일 뒤)이 찍힙니다. 도구가 그 id를 `output/facebook/test-post.json`에도 적어 두므로, **id를 잊어도 됩니다.** 그 글을 지우기 전에 이 명령을 다시 돌리면 도구가 **아무것도 올리지 않고 멈춥니다**(테스트 글이 두 건 쌓이지 않게).

2. **눈으로:** 페이스북 페이지 → **예약된 게시물** 목록에 그 글이 보이는지. 보이면 이 토큰으로 글을 올릴 수 있다는 것이 증명된 것입니다. 글 안의 `Tiếng Việt · မြန်မာ · नेपाली`가 **네모로 보이지 않는지**도 함께 보세요(네모로 보이면 현지어 글자가 페이스북에서 깨지는 것이므로 개발자에게 알리세요).

3. 확인했으면 지웁니다.

   ```
   npm run fb:test-post -- --delete
   ```

   id를 적지 않으면 1번에서 적어 둔 그 글을 지웁니다(`npm run fb:test-post -- --delete <사진 id>`처럼 적어도 됩니다).

   **지우기 전에 도구가 그 글의 본문을 읽어 테스트 글과 같은지 대조합니다.** 다르면 **아무것도 지우지 않고** 멈춥니다 — 그 달의 게시물 id(원장 `scheduled.json`의 `"결과"` 값)를 잘못 붙여넣는 사고를 막기 위해서입니다. 그것을 지우면 페이스북에서는 게시물이 사라지는데 원장에는 줄이 남아, 그 게시물은 **조용히 영영 나가지 않습니다.**

   **눈으로:** 예약된 게시물 목록에서 그 글이 사라졌는지. 지우지 않고 두면 30일 뒤에 **실제로 공개됩니다.** 도구가 "지웠습니다"라고 말하지 않으면(본문을 읽지 못했다, 본문이 다르다, 지워졌는지 알 수 없다 — 어느 쪽이든) 페이스북 페이지의 예약된 게시물에서 직접 지우세요.

1번에서 화면이 말하는 것을 그대로 따릅니다. 둘을 가려 말해 줍니다.

- **거절당했다고 나오면** 글은 올라가지 않았습니다. 토큰에 올리기 권한이 없을 수 있으니 1-1로 돌아가 권한 세 개를 다시 확인하세요.
- **"답을 받지 못했다 / 올라갔을 수 있다"고 나오면** 권한 문제가 아닙니다. 글이 올라갔는데 사진 id를 받지 못한 것일 수 있으므로, 예약된 게시물 목록에서 `[테스트]`로 시작하는 글을 찾아 **있으면 직접 지우세요**(그 글이 보이면 올릴 수 있다는 증명은 된 것입니다).

### 6-3. 첫 달의 되번역 파일을 지우지 말아 두세요

첫 실제 월의 `backtranslation.json`은 개발자가 **실제 되번역으로** 한 가지를 재 보는 데 씁니다(3-4의 구멍을 주어 탐지 없이 닫을 수 있는지). 지어 낸 문장으로는 잴 수 없는 값입니다. 그 달 폴더를 지우지 말고 남겨 두세요.

## 7. 손대지 말 것

### 7-1. **네트워크 재시도를 달지 마세요** (개발자에게)

"인터넷이 불안하니 자동으로 다시 보내게 하자"는 생각이 가장 위험합니다. 사진 예약은 같은 요청을 두 번 보내면 **게시물이 두 개 만들어집니다.** 그리고 그렇게 생긴 **중복**은 도구가 알지 못해 원장에도 남지 않습니다 — 아무도 알아챌 수 없습니다. 도구는 일부러 재시도를 달지 않았습니다(`scripts/facebook/cli.py`에 그 까닭이 주석으로 적혀 있습니다). 네트워크가 불안할 때 할 일은 **같은 명령을 다시 실행하는 것**입니다. 이미 올린 건은 원장을 보고 건너뜁니다.

### 7-2. 첫 실제 월을 보기 전에는 아무 수치도 조정하지 마세요

- 글자 차이의 임계값(0.45)을 올리거나 내리지 마세요. 3-1에서 보듯 **가를 수 있는 값이 없습니다.**
- `역번역중복` 경고를 끄지 마세요(한 달 스무 건은 정상입니다).
- 강조 칩이 많다고 필터를 넣지 마세요. 거의 같은 글에서 필터가 꺼지는데, 뒤집힌 부정이 숨는 곳이 바로 그 거의 같은 글입니다.

조정해야 할 것이 있는지는 **첫 실제 월의 실제 되번역을 보고** 판단합니다.

### 7-3. 사실 파일에 출처 없는 수치를 넣지 마세요

`output/facebook/facts.json`의 모든 항목에는 값·출처 주소·확인자·확인일·유효기한이 있습니다. 하나라도 비면 멈춥니다. 유효기한은 **각 게시물의 게시일**로 판정하므로, 오늘 유효해도 25일 뒤 게시일에 만료되는 사실은 오류가 됩니다.
